# Прогрес і що далі

Робочий файл для продовження між сесіями. Оновлювати в кінці кожної сесії.
Спека: [spec-v3.md](spec-v3.md). Конвенції коду: [CLAUDE.md](../CLAUDE.md).

Оновлено: 2026-09-10, після зрізу 2.

## Стан

**Інфра.** Репо `imax/familyOS`, публічне, MIT. 2026-09-09 у публічний репо потрапили
справжні імена сім'ї; репо видалено на GitHub і перестворено з чистою історією, усі імена
в репо тепер вигадані (Олег, Анна, Оля, пані Марія, Петро), правило є в CLAUDE.md.
Python 3.12 + uv, ruff, pytest.
**Задеплоєно 2026-09-10:** https://family-ea.fly.dev, app `family-ea` (назва `familyos`
зайнята), одна машина shared-cpu-1x у `fra` (Варшави у Fly нема), volume `data` 1 GB →
`/data/family.db`. Деплоїти тільки `fly deploy --ha=false`: дві машини означали б два
polling-и одного бота і два SQLite. Секрети на Fly: `ADMIN_USER_ID`, `ANTHROPIC_API_KEY`,
`OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `WEB_USER`, `WEB_PASSWORD`, `WEB_URL`.

**Зріз 1 — зроблено.** Пайплайн повідомлення повністю: store → контекст → один
`messages.parse()` → apply ops → відповідь. Бот (allowlist з таблиці `members` + env
`ADMIN_USER_ID`, `/start` `/debug` `/facts` `/web`, текст, голос через OpenAI
`gpt-4o-transcribe`). Web (basic auth, `GET /` з бакетами today/overdue/open + memories +
`?q=`, `GET/POST /facts` з textarea, `GET/POST /family`, `GET /messages`). Facts: людський
стабільний фон, версії в таблиці, цілком у контексті LLM. REPL без Telegram:
`uv run python -m family_ea chat --as oleh --name Олег` (`--name` створює member на
порожній базі). 36 детермінованих тестів, LLM підмінений.

**Зріз 2 — зроблено (2026-09-10).** Ранковий дайджест: JobQueue щодня о `DIGEST_TIME`
(08:30 Kyiv), кожному члену сім'ї той самий текст: «Сьогодні» + «Прострочено», а «Без
дати» лише по понеділках, щоб не набридало. Порожньо → мовчить. Без LLM: текст рендерить
код, це презентація, а не розуміння. Пуш зберігається як повідомлення бота, тому відповідь
на нього («Марію закрий») має контекст. `/today` показує те саме на вимогу, з «без дати».
Web done/drop зробили і того ж дня викинули: виглядало жахливо, закриття лишається через
чат. iCal:
на web лінк «📅» → `/commitments/:id.ics` біля кожної справи з датою; в Telegram кнопка
«📅 …» під відповіддю бота (для щойно створених/змінених справ з датою) і під дайджестом,
яка присилає `.ics` файл: тап → календар телефону пропонує додати. Точний час → подія на
годину, вікно → all-day.

**Живий Claude і Telegram працюють.** 2026-09-10 через REPL: повідомлення з фактом і
справою дало memory + commitment з `due_from` на завтра, питання «хто ремонтував котел?»
відповіло з контексту без операцій. Через бота локально: `/start` від адміна створив
member, повідомлення з двома справами дало два commitments з правильними датами (вікно
на завтра і точний час). Sonnet 5, ~2 с, ~3.8k вхідних токенів на виклик. Голосові ще не
пробували.

## Наступні кроки

1. **Користуватись задеплоєним ботом.** База на Fly свіжа: адмін пише `/start`, додає
   другу людину на `/family`. Спробувати голосове. Прогнати сценарії A, E, G, I, K зі
   спеки §11, дивитись `/debug`: чи правильно парсить дати, чи не дублює, чи закриває за
   id. Правити промпт у `llm.py`, редеплой `fly deploy --ha=false`.
2. **Події окремо від справ.** Рішення 2026-09-10: окрема таблиця `events` (не
   колонка `kind`), бо різниця в даних означає менше помилок у коді; з `until`
   (тривалість). Подія минає, а не протерміновується; справа робиться або прострочується.
   LLM вирішує, що є що. Дайджест: порядок дня за часом, потім справи, потім прострочено.
   Web: дві секції. Спека далі не орієнтир, ідемо від болю.
3. **Перевірити наживо.** Перший дайджест о 08:30, «📅» у Telegram і на web з телефона.
4. **Сценарні тести через LLM** (§13): сценарії як JSON (вхід → очікувані ops), скрипт
   ганяє через справжню модель і порівнює. Потрібно, щоб міняти промпт і модель
   (порівняти `claude-haiku-4-5`) без регресій.
5. Два тижні реального використання, далі за болем.

## Прийняті рішення

**People → facts (2026-09-09).** Окремої сутності «люди» нема. Є дві речі:

- `FAMILY=id:telegram_id:ім'я,...` в env — хто пише боту. Allowlist це безпека, не знання,
  LLM його не редагує.
- **Facts** — один вільний текст, стабільний фон про сім'ю (хто є хто, адреси, звички).
  Спочатку порожній, редагує тільки людина: textarea на web (`/facts`, єдиний виняток із
  «web тільки читає») і `/facts` у боті, щоб подивитись. Кожне збереження — нова версія
  в таблиці `facts`. Іде в контекст LLM цілком. LLM facts не пише.

Усе, що люди розповідають боту (події, контакти майстрів, хто що сказав), — memories.
Якщо за два тижні виявиться, що бот постійно вивчає стабільні речі як memories, додати
LLM-операцію «запропонувати зміну у facts» з підтвердженням людиною. Онбординг як
LLM-розмова, що сама складає facts, — v1.5.

**Members у базі, не в env (2026-09-10).** `FAMILY=id:tg:name,...` було незручно
накручено. Тепер в env тільки `ADMIN_USER_ID`: цю людину бот пускає завжди і після першого
повідомлення сам створює їй рядок у `members` з імені в Telegram. Решту додає адмін на
web `/family` (ім'я + Telegram id; id-слаг для LLM робиться з імені транслітерацією,
Олег → oleh). Коли боту пише чужий, він отримує «приватний бот» + свій id, а адмін —
повідомлення в Telegram з лінком на `/family?name=…&telegram_id=…`, де форма вже
заповнена. Allowlist у боті живий (фільтр дивиться в базу на кожне повідомлення), тому
додавання на web діє без рестарту.

## Відкриті рішення

**Модель.** `claude-sonnet-5`, effort `medium`, обидва з env. Haiku порівняти, коли
будуть сценарні тести.

## Відхилення від спеки

- `messages.chat_with` — чий це чат; без цього відповіді бота в контексті не мають адресата.
- `messages.llm_result` зберігає `{model, usage, request_id, output, applied}`, не голий вихід.
- Commitments у зрізі 1, а не 2.
- `TRANSCRIPTION_API_KEY` → `OPENAI_API_KEY`, транскрипція через httpx, без openai SDK.
- Замість `family.yaml` (§4 спеки) — таблиця `members` (адмін веде на web, в env лише
  `ADMIN_USER_ID`) + facts (нова таблиця, людина веде), решта людей у memories.
- Web має POST: `/facts`, `/family`; і `.ics` на справу. Done/drop на web викинуто.
- Дайджест без LLM і о 08:30, не 08:00; «без дати» лише по понеділках. `/today` і iCal
  (web + Telegram) у спеці не було.

## Дрібниці

- pyenv на цій машині без 3.12: голий `python3` у теці падає на системний 3.9 з
  попередженням. `uv run` це не зачіпає. Ліки: `pyenv install 3.12` або ігнорувати.
- FastAPI-модулі без `from __future__ import annotations` (ламає `Annotated` dependency).
- SQLite `LIKE`/`lower()` ASCII-only; для українського пошуку є `ufold()` у `db.py`.
- Тести, що перевіряють дати в контексті, підміняють `family_ea.db.utc_now_iso` через
  monkeypatch, інакше вони дрейфують разом із календарем (так упав тест 10.09).
- Локальний `serve` і Fly з одним токеном одночасно не запускати: Telegram дає 409 на
  getUpdates. Локально є `chat` REPL; для живого бота на ноуті треба окремий dev-бот.
- Локальна `data/family.db` має тестові записи від 10.09; на Fly їх нема, і не треба.
